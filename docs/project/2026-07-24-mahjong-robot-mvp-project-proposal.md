> 版本：v0.1  
> 日期：2026-07-24  
> 项目代号：AGILE Mahjong Robot  
> 当前阶段：Demo/MVP 立项与方案确认

---

## 1. 项目概述

本项目拟构建一套“机械臂 + 视觉 + 麻将 AI”的自动对弈 Demo/MVP。系统根据当前手牌与可见牌状态，自动计算应打出的麻将牌，并由松灵 PiPER 6 轴机械臂完成物理出牌动作。

MVP 的核心目标不是一次性完成全自动麻将机、完整四家自动对弈或复杂理牌系统，而是先打通最小闭环：

```text
手牌/场况输入 -> AI 决策 -> 目标牌定位 -> PiPER 机械臂推倒/打出 -> 状态更新
```

该闭环能证明项目的核心价值：麻将策略决策可以与真实物理执行结合，形成可演示、可迭代的具身智能麻将系统。

---

## 2. 项目背景与价值

### 2.1 背景

现有自动麻将桌主要解决洗牌、码牌和发牌问题，但通常不具备智能决策与通用机械臂操作能力。商业级麻将机器人已开始出现，例如灵初智能 PsiBot 在 WAIC 2025 展示的麻将机器人，但该类整机方案不开源，无法直接复用。

开源生态中，麻将 AI、牌效计算、视觉检测和机械臂控制各自已有成熟组件：

- 决策侧：Shanten、Ukeire、Mortal、Akagi、国标麻将算法库等。
- 视觉侧：YOLO 系列检测、麻将牌分类数据集与课程项目案例。
- 执行侧：PiPER 官方 `piper_sdk`、ROS2 Humble、MoveIt 2、Gazebo 仿真。

因此，本项目适合采用“组合集成 + 关键闭环自研”的方式推进。

### 2.2 项目价值

1. 展示 AI 决策与机械臂物理执行结合的完整闭环。
2. 为后续自动陪玩、教学、训练、比赛辅助或具身智能展示打基础。
3. 沉淀麻将牌识别、桌面坐标标定、PiPER 操作、策略接口等可复用模块。
4. 通过 Demo 快速验证方向，降低后续投入的不确定性。

## 3. 项目目标

### 3.1 MVP 目标

在真实桌面环境中完成一次可重复演示：

1. 系统获得当前手牌与可见牌信息。
2. 决策模块计算推荐出牌。
3. 视觉模块定位目标牌在桌面/牌架中的位置。
4. PiPER 机械臂移动到目标位置。
5. 机械臂将目标牌推倒或打出到指定区域。
6. 系统记录本次动作结果，并准备下一轮决策。

### 3.2 非目标

MVP 阶段暂不追求：

- 完整自动洗牌、码牌、发牌。
- 完整四家全自动物理对弈。
- 复杂碰、杠、吃、胡的全部机械执行。
- 从版权书籍中爬取或复制策略内容。
- 一开始就训练强麻将大模型。

| 状态记录 | 记录本次决策、目标牌、动作结果与失败原因 |

### 5.2 非功能需求

| 维度 | 目标 |
|---|---|
| 可演示性 | 单次出牌闭环稳定可重复 |
| 实时性 | 决策 + 定位 + 执行控制在可接受演示节奏内 |
| 可解释性 | 能说明为什么打这张牌 |
| 本地运行 | 核心决策和控制优先本地运行 |
| 合规性 | 不使用未授权书籍、私有权重或违反 ToS 的数据 |
| 可扩展性 | 规则、视觉模型、执行动作均可替换 |

## 6. MVP 技术方案

### 6.1 总体架构

```text
+-------------------+
|   演示界面 / API   |
+---------+---------+
          |
          v
+-------------------+        +------------------+
|   世界状态管理     | <----> |  手牌/弃牌输入   |
+---------+---------+        +------------------+
          |
          v
+-------------------+
|  决策引擎           |
|  Shanten/Ukeire     |
|  + 启发式策略       |
+---------+---------+
          |
          v
+-------------------+
|  目标牌选择器       |
|  牌型 -> 实体牌     |
+---------+---------+
          |
          v
+-------------------+        +------------------+
|  视觉定位模块       | <----> |  顶置相机         |
|  YOLO/分类/标定     |        +------------------+
+---------+---------+
          |
          v
+-------------------+
|  运动规划模块       |
|  坐标转换 + 路径    |
+---------+---------+
          |
          v
+-------------------+
|  PiPER 执行层       |
|  ROS2 / MoveIt SDK |
+-------------------+
```

### 6.2 决策方案

MVP 推荐采用“规则牌效核心 + 可选 AI 增强”的路线。

第一阶段：

- 计算 Shanten（向听数）。
- 计算 Ukeire（有效进张）。
- 对每张候选弃牌打分。
- 加入简单启发式：保留两面搭子、减少孤张、考虑安全牌和可见牌。
- 输出推荐弃牌及解释。

第二阶段：

- 若采用日麻，可评估 Mortal / Akagi / mjai 协议。
- 若采用国标，可评估 `mahjong-algorithm`、`ChineseOfficialMahjongHelper`。
- 使用公开牌谱数据进行自训练或蒸馏，但不作为 MVP 阻塞项。

### 6.3 视觉方案

MVP 推荐固定俯视相机：

1. 相机固定在牌桌上方或侧上方。
2. 标定相机坐标系与桌面坐标系。
3. 使用 YOLO 检测麻将牌位置。
4. 对目标牌区域做牌面分类，或在 Demo 阶段用贴纸/标记降低识别难度。
5. 输出目标牌中心坐标 `(x, y)` 与朝向 `theta`。

如果视觉识别短期不稳定，可采用降级方案：

- 手牌由人工摆在固定槽位。
- 每个槽位对应固定坐标。
- AI 只决定“第 N 张牌”，机械臂按槽位坐标推倒。

该降级方案仍然能演示完整决策到物理执行闭环。

### 6.4 机械执行方案

MVP 推荐优先“推倒/推出”，不优先“夹起打出”。

推倒动作流程：

1. 移动到目标牌侧方接近点。
2. 末端夹爪侧面或简易推板对准目标牌。
3. 低速水平推动 3-5 cm。
4. 目标牌离开手牌区域或倒入弃牌区。
5. 机械臂撤离到安全位。
6. 相机复检动作结果。

推荐原因：

- 不需要精确夹持薄而光滑的麻将牌。
- 对夹爪力控要求低。
- 动作链短，演示成功率更高。
- 便于先完成最小闭环。

## 7. 分阶段计划

### MVP0：纯软件决策闭环

| 内容 | 说明 |
|---|---|
| 目标 | 输入手牌，输出推荐弃牌 |
| 工作 | 选定规则；接入牌效库；实现弃牌评分；提供 CLI/简单 Web UI |
| 验收 | 给定 20 组测试手牌，系统能输出推荐弃牌与解释 |
| 预计周期 | 3-5 天 |

### MVP1：决策 + 机械臂推倒指定牌

| 内容 | 说明 |
|---|---|
| 目标 | AI 决策后，PiPER 推倒指定实体牌 |
| 工作 | 槽位标定；PiPER 基础运动；推倒轨迹；安全位；失败复检 |
| 验收 | 固定 10 次出牌测试，成功率不低于 80% |
| 预计周期 | 1-2 周 |

### MVP2：视觉识别 + 自动定位

| 内容 | 说明 |
|---|---|
| 目标 | 相机自动识别牌位并定位目标牌 |
| 工作 | 相机标定；采集 500-1000 张图像；YOLO 微调；牌面分类 |
| 验收 | 常规光照下目标牌定位成功率不低于 85% |
| 预计周期 | 1-2 周 |

### MVP3：夹取/打出与完整演示包装

| 内容 | 说明 |
|---|---|
| 目标 | 机械臂将牌夹起或吸起并移动到弃牌区 |
| 工作 | 夹爪/吸盘评估；抓取位姿；放置动作；演示界面 |
| 验收 | 完成 3-5 轮连续出牌演示 |
| 预计周期 | 2-4 周 |

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 麻将规则未定 | 决策库选择不确定 | 策略接口可插拔；先用最成熟规则验证闭环 |
| 视觉识别不稳定 | 找不到目标牌或误识别 | 先用固定槽位/标记牌降级；逐步训练真实模型 |
| 夹爪夹取打滑 | 出牌失败 | MVP 先推倒；二期评估真空吸盘或定制夹爪 |
| WSL2 USB-CAN 不稳定 | 机械臂通信中断 | 必要时切实体 Ubuntu 22.04 |
| Mortal AGPL 许可证 | 商业闭源集成风险 | MVP 用自研牌效；Mortal 仅独立进程或研究参考 |
| 版权数据风险 | 项目合规问题 | 不抓取版权书；使用公开 Wiki、论文、CC BY 数据 |
| 真实桌面遮挡 | 视觉和动作失败 | 设计 Demo 专用牌架和固定弃牌区 |

## 12. 推荐技术路线结论

建议项目按以下路线推进：

1. **先做 MVP0 软件决策**：不要先陷入大模型训练和复杂视觉。
2. **再做 MVP1 固定槽位推倒**：用确定坐标证明 PiPER 可稳定出牌。
3. **再接 MVP2 视觉定位**：让相机识别目标牌位置。
4. **最后做 MVP3 夹取/完整包装**：提升真实感与演示效果。

一句话总结：

> 第一版 Demo 的胜负手不是训练出最强麻将 AI，而是尽快证明“AI 决定哪张牌，机械臂能稳定把那张牌打出去”。

## 13. 硬件与前端构想

### 13.1 硬件分层

当前建议把系统拆成“训练电脑 / 主控板 / 视觉模组 / 机械臂”四层，避免所有任务挤在一台设备上。

```text
GX10 小主机 / PC
  - 训练 YOLO 识牌模型
  - 调试识别效果
  - 运行电脑端前端 UI
  - 需要时作为高算力备用推理端

香橙派
  - 作为机器人主控
  - 维护状态机
  - 接收视觉结果
  - 通过串口/CAN/网络同步数据
  - 下发 PiPER 动作指令

二哈视觉 2
  - 部署自训练 YOLO 识牌模型
  - 输出牌型、目标框、置信度
  - 通过串口/I2C/USB 与香橙派或电脑同步

松灵 PiPER 机械臂
  - 接收目标坐标和动作模式
  - 执行推倒/推出/二期夹取动作
```

### 13.2 数据流

```text
二哈视觉 2 识别牌型与位置
  -> 香橙派接收识别结果
  -> 决策模块选择最优弃牌
  -> 香橙派生成动作请求
  -> PiPER 执行推牌动作
  -> 电脑端 UI 展示状态、日志和结果
```

第一版推荐让电脑端 UI 作为“操作台”，香橙派作为“机器人主控”，二哈视觉 2 作为“前端视觉传感器”。如果二哈视觉 2 的识别精度不足，再切换为 GX10/PC 侧推理。

### 13.3 电脑端前端 UI 构想

电脑端 UI 不做营销页，应做成真正的“麻将机器人控制台”。核心页面如下：

| 页面 | 功能 |
|---|---|
| 总览 Dashboard | 显示系统在线状态、相机状态、香橙派连接、PiPER 连接、当前回合 |
| 视觉识别页 | 展示实时画面、牌型框、置信度、识别日志 |
| 手牌状态页 | 显示当前手牌、可见牌、推荐弃牌、替代候选 |
| 决策解释页 | 展示向听数、有效进张、弃牌评分、为什么打这张 |
| 机械臂控制页 | 手动回零、急停、低速测试、执行推牌、撤离安全位 |
| 训练数据页 | 采集样本、保存截图、标注状态、模型版本 |
| 演示模式页 | 一键进入演示流程，适合给观众/评委展示 |

### 13.4 UI 风格建议

- 整体应是科技控制台，而不是普通网页介绍。
- 左侧为系统导航，右侧为实时状态区。
- 主色建议深色或中性灰黑，配绿色/青色状态灯。
- 画面中心应突出实时相机画面与麻将牌识别结果。
- 按钮必须包括急停、回零、执行、暂停、复检。
- 演示模式要尽量少按钮，便于现场稳定操作。

## 14. 项目叙事与优势

### 14.1 基地背景

本项目可与松山湖硬科技创业生态建立叙事连接。XbotPark 官网公开信息显示，松山湖机器人产业基地由李泽湘教授等于 2014 年发起，是面向青年工程师和硬科技创业团队的创新创业平台。公开资料也提到松灵机器人与李泽湘教授的孵化生态相关。

对外宣传建议采用稳妥表述：

> 项目团队在松山湖硬科技创业生态中完成早期探索，并基于松灵 PiPER 机械臂进行具身智能麻将 Demo 开发，尝试把机器人、视觉识别和策略 AI 融合到真实桌面任务中。

避免使用未经确认的绝对表述，例如“官方联合项目”“基地授权项目”等。

### 14.2 团队年轻

团队平均年龄不超过 18 岁，这是非常强的传播点。建议突出：

- 年轻团队敢于做复杂硬件系统。
- 不只做软件 Demo，而是把 AI 落到真实机械臂执行。
- 项目横跨视觉、机器人控制、策略算法、前端交互、现场演示。

宣传表达建议：

> 一支平均年龄不到 18 岁的年轻团队，尝试用真实机械臂完成麻将自动对弈 Demo，从识牌、算牌到出牌，完整打通 AI 与物理世界的闭环。

### 14.3 技术优势

本项目的技术优势建议围绕三点展开：

1. **自训练视觉模型**  
   使用团队自采麻将牌数据，训练 YOLO 识牌模型，适配真实牌、真实光照和真实桌面环境。

2. **自驱动决策闭环**  
   系统不是单纯识别图片，而是能根据牌效算法和策略规则主动选择出牌。

3. **自操控机械执行**  
   决策结果最终由 PiPER 机械臂执行，形成“识别 -> 决策 -> 操作”的具身智能闭环。

对外宣传可简化为：

```text
自训练识牌模型
+ 自主策略决策
+ 自驱动机械臂出牌
= 真实世界中的智能麻将机器人 Demo
```
